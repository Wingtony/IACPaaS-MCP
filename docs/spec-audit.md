## Требования MCP-сервера (разделы 4–5)

| Требование | Состояние и основание |
|---|---|
| Фактический адаптер IACPaaS, соответствие tool → operation | Реализовано: `backend.py`, таблица README. Экспорт через GET `/api/data/export/user-item`, обновление через PUT `/api/data/update`, импорт через POST `/api/data/import`. Чтение проверялось на реальной базе. |
| Локальный stdio и современный HTTP-транспорт | Реализованы stdio и Streamable HTTP; автоматические тесты транспорта и авторизации. |
| Единый слой доменной логики | Один `build_server`, общие backend, graph, knowledge, policy для транспортов. |
| Типизированные модели и JSON Schema входов/выходов | Частично: типизированные параметры, Pydantic KnowledgePlan и схемы MCP есть; большинство результатов объявлены общим `dict[str, Any]`. Предметные модели результатов и ошибок нужны для строгого выполнения требования типизации выходов. |
| Не включать лишние внутренние поля в tool schema | Публичные входы ограничены аргументами инструментов. Секреты платформы не являются аргументами модели. |
| Разделить чтение и изменение | Реализованы отдельные tools и read/write-аннотации. |
| Подтверждение или policy gate для изменения | Реализовано. По умолчанию запись запрещена; при разрешении используется предпросмотр и одноразовый токен, привязанный к операции. Проверено на mock. Живая запись в пользовательскую базу не подтверждена. |
| Структурированные результаты, диагностируемые ошибки | Сервер возвращает structured results / MCP tool errors. Ошибки HTTP и лимитов обрабатываются; часть конкретики платформы намеренно заменяется общими сообщениями. |

В таблице раздела 4 прямо сказано, что названия инструментов — предложение. Поэтому `update_concept` вместо `write_inforesource` и `import_inforesource` вместо `export_import_json` сами по себе не являются нарушением. Описание universal/meta/simple в разделе 2 не является явным требованием реализовать все три формата: сейчас используется universal. Проверка JSON базовая, без доказательства соответствия онтологии; в ТЗ запрошена проверка JSON/структуры, а не полноценный онтологический валидатор.

`list_inforesources` возвращает известные подключённые пути из конфигурации. Это документировано, но автоматического обнаружения всех доступных ресурсов учётной записи нет. В приёмочных сценариях область поиска необходимо называть «подключённые ресурсы», а не «весь фонд».

## Требования агента (раздел 6)

| Требование | Состояние и основание |
|---|---|
| Интерпретировать естественный язык как задачу над графом | Реализовано для ограниченного набора предметных операций. Неподдерживаемые составные запросы требуют уточнения; это не универсальный язык запросов к графу. |
| Выбирать tools, формировать аргументы, использовать результаты следующих шагов | Частично. Основной режим `run_planned_agent` получает каталог, просит Qwen сформировать KnowledgePlan и вызывает фиксированный `query_knowledge`. Qwen выбирает операцию внутри плана, а не произвольную последовательность MCP-инструментов. |
| Уточнять недостающие критические параметры | Есть разрешение неоднозначных марок, неизвестных объектов и неподдерживаемых условий. Для рейтинга без указанной границы применяется явно подписанное допущение; критичность такого допущения нужно оценивать в сценарии. |
| Проверять достаточность результата и при необходимости вызывать следующий tool | Полностью не выполнено в основном режиме. Повторная проверка по снимку подтверждает вычисления, но не заменяет оценку достаточности агентом и адаптивное продолжение поиска. |
| Представлять API-ошибки агенту для корректировки плана | Частично. MCP-сервер выдаёт ошибки, но основной планировщик при ошибке предметного запроса завершает ответ общим исключением; результат не возвращается Qwen для перепланирования. Повтор HTTP 500 модели и исправление JSON-плана — другие механизмы. |
| Отдельная политика записи | На сервере есть. В основном предметном режиме операций записи нет. Альтернативный цикл `_run_agent` имеет обработку подтверждений, но не является режимом сайта по умолчанию и не выведен отдельным аргументом CLI. |
| Два режима: VS Code Agent Host и standalone | Standalone реализован; конфигурация VS Code подготовлена, обязательная демонстрация в IDE отсутствует. |

В `agent.py` сохранён альтернативный итеративный цикл `_run_agent` с tool calling и передачей tool results модели. Само наличие этого кода не доказывает выполнение требований основным поставляемым режимом: нужны доступный способ запуска, согласованная политика безопасности и приёмочные проверки.

Таблицы ответов строятся кодом по данным базы. Это не заранее написанные ответы на вопросы из тестового банка. Тем не менее конечный набор операций и отсутствие адаптивного цикла остаются ограничениями.

## VS Code и standalone (разделы 7–8)

- `.vscode/mcp.json`, `.github/agents/iacpaas.agent.md` и инструкции запуска/диагностики имеются.
- **Три сценария непосредственно в VS Code не продемонстрированы.** Тест stdio-подпроцесса не заменяет эту демонстрацию.
- Standalone использует тот же `build_server` и MCP API. CLI поддерживает stdio и подключение к HTTP; Web использует MCP-клиент того же сервера внутри процесса.
- Собственный Python runtime допустим по формулировке «LangChain/LangGraph или сопоставимый агентный runtime». Обязательной зависимости именно от LangChain нет. Сопоставимость следует подкрепить рабочим циклом выбора инструментов, проверки результата и перепланирования.
- CLI, HTTP/UI и JSONL-трассы реализованы.

## Приёмочные сценарии (раздел 9)

Чтение ресурса, ограниченный подграф, подсчёты, неправильный путь, превышение глубины и подтверждение изменения покрыты автоматическими тестами. Есть отдельные проверки stdio и HTTP. Для демонстрации всей системы нужно дополнить их агентным сценарием «найти ресурс → получить данные» с зависимостью второго вызова от первого и пройти один и тот же сценарий в VS Code и standalone.

22.10.2026 при аудите повторно запущен `python -m pytest -q`: **109 passed in 6.94s**. Реальная Qwen этими тестами не загружается. Предыдущие реальные проверки базы и Qwen описаны в `benchmark-results.md`; в этом аудите они заново не запускались. Число прошедших тестов не подтверждает исполнение непроверенных требований IDE или адаптивного агента.

## Комплект сдачи (раздел 10)

Исходники, схема архитектуры, установка, инструкции MCP/VS Code/standalone присутствуют. README содержит устаревшие сведения в начале: автоматическая выгрузка после каждого вопроса, старое поведение Start-Agent.cmd и ручная остановка окна сервера противоречат актуальному разделу управления в конце. 3. Пройти и зафиксировать минимум три сценария в VS Code; один повторить через standalone, включая зависимые вызовы.
4. Согласовать README, архитектуру, инструкции запуска и ограничения с фактической поставляемой реализацией.
