# Проверяемые ответы и контекст

Основной веб-агент использует адаптивный цикл (`adaptive_agent.py`): модель выбирает реальные MCP-инструменты и аргументы, проверяет достаточность ответа, получает ошибки для перепланирования. Для предметных расчётов она может выбрать `query_knowledge` с `knowledge.KnowledgePlan`. Итоговые факты отображает код по выбранным моделью сохранённым источникам; неподтверждённый свободный текст не принимается. Повторная проверка по экспортам сопоставляет результат, порядок и текст. SHA-256 проверяет целостность локального снимка, а не истинность данных платформы. Достаточность оценивает модель; верность понимания вопроса не объявляется гарантированной. Лимит шагов, усечённый или неполный результат не получают статус полной проверки.

Точные материалы разрешаются по нормализованной марке; омографы кириллицы/латиницы нормализуются. При нескольких объектах задаётся уточнение. Карточка железа ищется в базе химических элементов, а не среди всех упоминаний Fe в составах. Числа, интервалы, ≤/≥ и формулы сохраняются. Сравнение и рейтинг выполняются кодом на полном наборе кандидатов, ограничение limit применяется после расчёта. Если нужная граница отсутствует или расчётная, она не превращается в ноль и не участвует в числовом отборе. Неоднозначные и отсутствующие данные показываются явно.

Экспорты: logs/exports/<sha256>.json. Запросы, решения модели, результаты инструментов, ошибки и проверка: logs/web-*.jsonl, logs/agent-*.jsonl и соответствующие каталоги -sources. Снимки доступны из карточки проверки. Локальный SQLite-индекс хранится в logs/search.sqlite3; кеш экспорта не старше 5 минут. Запрос повторно читает ресурс после истечения кеша. Полные графы не передаются модели автоматически.

Контекст адаптивного цикла учитывает вопрос, системную инструкцию, схемы инструментов, историю и наблюдения. Результаты длиннее 7000 символов заменяются обзором полей и JSON Pointer; оригиналы остаются в EvidenceStore. При превышении бюджета старые наблюдения заменяются ID источников. `read_evidence` позволяет прочитать точное поле повторно. Сжатие затрагивает только ввод модели, а не расчёт или сохранённый результат. Если даже вопрос и схемы не помещаются, приложение сообщает об ошибке без скрытого обрезания вопроса.

История пользователя целиком хранится в logs/web.sqlite3. Для Qwen приложение собирает краткую память типизированных задач: операция, марка, класс, элемент, порог, граница, порядок и показанные марки. Пока история помещается в бюджет, сохраняются все реплики. При переполнении старые полные пары заменяются памятью до восьми последних исключённых задач; нет прежнего фиксированного ограничения в шесть реплик. Это сжатие состояния, а не LLM-пересказ фактов; поздние факты снова проверяются чтением MCP. Исторические ответы без таких метаданных используются только в пределах последних реплик. Ветвление при редактировании сохраняет исходную историю.

Текущий контекст Qwen — 32768 (`AGENT_CONTEXT_LENGTH`), бюджет входа — около 24000 (`AGENT_CONTEXT_BUDGET`), максимальная генерация плана — 2048 (`OLLAMA_NUM_PREDICT`). Оценка UTF-8 bytes / 2 приблизительная и не является токенизатором. Текущий вопрос не обрезается скрыто. Нет гарантии скорости/памяти на максимально заполненном контексте. В веб-режиме модель остаётся загруженной между вопросами. Она выгружается при остановке приложения; по запросу пользователя отменено прежнее освобождение памяти после каждого ответа.

Доступ IACPaaS: JWT через POST /api/signin. По явному запросу пользователя логин, пароль и JWT зашифрованы Windows DPAPI в .local/account.dpapi. Изменение — через «Подключение IACPaaS». В .env пароль и JWT не сохраняются. Все журналы, данные аккаунта, снимки, база истории и окружение исключены из Git.
