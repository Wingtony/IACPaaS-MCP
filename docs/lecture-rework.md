# Переработка после разбора лекции

## Что требовалось

Лекция требует реального информационного ресурса IACPaaS, одного стандартного MCP-сервера для IDE и собственного веб-агента, истории, автоматического ограничения/сжатия контекста и верификации. Примеры газов относятся к другой группе; наш предмет — материалы. Интерфейс участников демонстрации не является шаблоном, который нужно копировать.

Ключевое замечание преподавателя: корректный вызов API не гарантирует правильный ответ. Можно выбрать не тот объект, пропустить часть кандидатов, неправильно отсортировать диапазоны или исказить числа в финальном тексте. Промпт «не выдумывай» и проверка JSON сами по себе этого не предотвращают.

## Что было неудачно

Предыдущий агент передавал Qwen десять универсальных операций и большие результаты. После сжатия модель повторяла поиск; пользователь получал таблицу служебных полей, даже если значения были проверены. Сверка отдельных полей не проверяла полезность ответа. Увеличение контекста не исправляло эту архитектуру.

## Новая схема

1. Qwen получает вопрос, короткую структурированную память и последние реплики. Через Ollama `format` она формирует типизированный JSON KnowledgePlan; вложенные свободные вызовы инструментов не требуются.
2. В агентном цикле есть до трёх попыток исправить синтаксис плана. После успешного разбора выполняется предметный MCP-инструмент query_knowledge. Финального свободного пересказа моделью нет.
3. MCP выбирает информационную базу по операции. Онтология не подменяет реальные марки, описание свойства не выдаётся за измерение материала. Выбор отдельной базы в интерфейсе остаётся явным ограничением.
4. Код разрешает точную марку/название, извлекает состав и ограничения, считает весь набор и только затем ограничивает отображение. Рейтинг использует указанную верхнюю или нижнюю границу. Фильтр ≤ доказывается по верхней границе, ≥ — по нижней. Отсутствующее значение не считается нулём. Символическая формула не подменяется числом.
5. Исходные экспорты сохраняются с SHA-256. Независимый повторный запуск операции по этим снимкам сравнивает объект, строки, число, порядок и готовый текст ответа. При несовпадении ответ скрывается.
6. Пользователь видит нормальную предметную таблицу, интерпретацию запроса, источники и подробный план. Неоднозначное название требует уточнения. Проверка не обещает абсолютное понимание смысла и истинность исходного ресурса.
7. Полная переписка остаётся в SQLite. В модель передаются краткие записи предыдущих операций, объектов, ограничений и показанных марок плюс недавние реплики. Это детерминированное сжатие состояния задач на уровне приложения, а не команда пользователя «сожми чат». Будущие факты снова читаются через MCP.
8. «Изменить вопрос» создаёт ветку с историей до выбранного вопроса. Исходный диалог сохраняется.

## Границы реализации

Поддержаны обзор ресурсов, структура, список/число марок, состав и сравнение составов, элемент, описание свойства, термин, рейтинг и один числовой фильтр состава. Произвольная аналитика и неподдерживаемые вопросы требуют уточнения. Измеренная плотность конкретного материала не выводится из общего справочника свойств. Содержимое BLOB не индексируется. Для рейтинга неопределённое «содержание» требует выбора границы, потому что интервалы не задают фактическое содержание партии.

Семантический разбор Qwen остаётся вероятностным: ошибочный план может дать корректный ответ на другой вопрос. Поэтому план показывается пользователю; результат не помечается как «100% понимание вопроса». Нужны предметные сценарии проверки, а не только тесты транспорта.

Режим веб-агента предназначен для чтения. Низкоуровневые MCP-инструменты записи сохранены с прежним подтверждением; в текущей конфигурации запись отключена. Внутренний прежний цикл сохранён для регрессионных проверок безопасности и не используется веб-агентом.

## Проверка и сдача

Автоматические тесты: `.venv\Scripts\python.exe -m pytest -q`. В tests/test_knowledge.py проверены интервалы, сравнение границ, полный рейтинг до пагинации, точные карточки, неоднозначность, подмена финального текста и память. Реальные предметные результаты сохранены локально в logs/domain-check.json; проверки Qwen — в logs/rework-live-*.jsonl. Модель выгружается в finally после каждого запроса, ошибки и отмены.

VS Code использует тот же build_server через .vscode/mcp.json; добавлен query_knowledge. Нужны доступный MCP-хост и его собственный провайдер модели; настройка терминального агента использует локальную Qwen. Структура исходников, установка и локальный запуск описаны в README.md. Публикация исходников на GitHub для сдачи — отдельное действие; из лекции не следует разрешение публиковать пароль, токены, приватные экспорты или всю рабочую папку.

## Результаты проверки 21.10.2026

82 автоматические проверки пройдены. На реальных экспортированных данных получены 10 компонентов 12Х18Н10Т, карточка Fe с номером 26, 6 бронз; рейтинг Cr проверен по 1334 материалам (994 с пригодной верхней границей). С реальной Qwen успешно проверены исходный вопрос про железо, состав 12Х18Н10Т и продолжение «этого сплава». Каждая проверка возвращала verified_result и выгружала модель. Верификация снимков подтверждает соответствие полученным данным, но не гарантирует их химическую достоверность.

## Исправление запроса о нескольких онтологиях

Фраза «онтологии материалов и свойств материалов» раньше ошибочно использовалась как одна подстрока пути, поэтому получалась пустая таблица. Добавлен общий разбор списка названий/алиасов с наследованием типа «онтология» между частями фразы. Выполнение и повторная проверка используют одинаковый набор разрешённых ресурсов; читаются только выбранные графы. Неизвестное название требует уточнения. Пустой результат, уточнение и неполное чтение имеют отдельные статусы; зелёная отметка доступна только непустому полностью проверенному результату. Старые пустые ответы также больше не показываются зелёными. Регрессионный набор: 92 теста. Добавлена защита от потери конкретных целей в составном вопросе: общий обзор списка онтологий не расширяет запрос понятий двух явно названных ресурсов.
