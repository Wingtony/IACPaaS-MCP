# Проверка проекта

## Веб-интерфейс

Подключение настоящего аккаунта: вход через официальный `/api/signin` выполнен, восемь корневых вершин ресурсов из папки «Загрузки» успешно экспортированы. Исправлена поддержка ответа с JSON-строкой в `data`. Логин, пароль и JWT по запросу пользователя сохранены с Windows DPAPI; в интерфейсе добавлена редактируемая форма подключения. Повторное подключение через веб-форму с сохранённым паролем успешно, вкладка ресурсов показывает восемь путей. **55 passed**, без запуска LLM; новые тесты используют отдельные тестовые учётные данные и временные файлы, реальные настройки пользователя не меняют. Справочник по материалам содержит около 94 тысяч вершин по интерфейсу платформы: полная выгрузка и поиск по нему в рамках проверки аккаунта не выполнялись.

Текущее обновление: **51 passed** (около 3.6 секунды), без загрузки Qwen. Добавлены строгая проверка JSON Pointer и типа значения, блокирование выдуманных значений/неизвестных источников, обнаружение подмены снимка, пересчёт графа по экспорту, сверка карточки/подграфа/поиска, сжатие истории с сохранением текущего вопроса и целых tool-групп, проверка контракта signin. В браузере проверена карточка источников на настоящем результате учебного MCP, с отдельной демонстрационной историей (без LLM). Новая версия строгого формата ответа и сжатия ещё не прогонялась с живой Qwen; модель намеренно не запускалась. Реальный вход IACPaaS ожидает локального ввода данных пользователя.

Обновление дизайна: интерфейс «Атлас знаний» получил собственную композицию, новый знак, фиолетово-мятную палитру, тёмную боковую панель и увеличенный вес текста. Проверено в браузере без запуска модели. Набор тестов расширен до **34 passed**: подтверждена выгрузка модели запросом `keep_alive=0` как после успешного ответа, так и после ошибки. Эти проверки используют HTTP-заглушки и не запускают Qwen. После работ проверено отсутствие процессов Ollama.

После добавления веб-приложения: **32 passed**, около 3.5 секунд. Дополнительно проверены HTML/JS, CSRF и локальный источник запросов, сохранение истории в SQLite, передача контекста, события SSE, действия с ресурсами через MCP, подтверждение/отказ записи и отмена фонового запроса.

В браузере выполнен реальный запрос к установленной Qwen: «Сколько вершин, дуг и ссылок в доступной базе?». Модель вызвала `list_inforesources` и `count_graph`, вернула **8 вершин, 8 дуг, 1 ссылку**, явно отметила учебные данные. Время запроса — 26.2 секунды, 112 токенов ответа. Проверены раскрытие списка MCP-вызовов, вкладка данных с деревом графа, тёмная тема и восстановление диалога после обновления страницы.

Локальный адрес приложения: http://127.0.0.1:8770. Запуск: `Start-Web.cmd`. Текст ответа поступает целиком, шаги работы — по мере выполнения. Внешний доступ к реальной платформе по-прежнему требует учётных данных.

Дата: 21 октября 2026 года. Windows, Python 3.11.9, MCP SDK 2.3.0, Ollama 0.40.3. Использована установленная модель `qwen-agent:latest`, родитель `qwen3.8:27b-q4_K_M`, 27.3B, Q4_K_M. API модели сообщает поддержку tools и thinking. При проверке thinking выключен, контекст 8192.

## Что требует внешнего доступа или UI

Живая платформа IACPaaS не проверялась: нужны ключ/JWT и пути ИР пользователя. REST backend проверен по официальной документации и заглушкам. Формат ответа живой платформы, пути метавершин и семантику изменения терминальных значений необходимо проверить на копии базы.

Конфигурации MCP и custom agent для чата VS Code подготовлены. Вход в chat-провайдер, выбор модели и демонстрация через UI VS Code не выполнялись. Задачи VS Code запускают тот же проверенный Python CLI; сам выбор задачи через UI не автоматизировался.

LangChain/LangGraph не используются: агентный цикл реализован напрямую через официальный MCP SDK и Ollama. Если формальное задание требует именно LangChain/LangGraph, потребуется адаптация этого слоя.
