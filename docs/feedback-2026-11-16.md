# Замечания при проверке 16 ноября 2026

## Доступ к сайту

`ATLAS_ALLOWED_HOSTS` проверяет адрес сайта в заголовке Host, а не IP посетителя. Для сайта `http://192.168.0.100:8770` нужен `192.168.0.100`; адрес клиентского ноутбука не нужен. Это защита от чужого Host/DNS rebinding, не сетевая ACL. Доступ к данным требует пароля АТЛАС; 401 в журнале означает отказ без него. Ограничение клиентских IP настраивается на firewall/прокси. Установка сейчас общая: авторизованные участники видят общую историю и настройки. Подробности: [Docker](docker.md).

## Что означает «сверены со снимками»

1. Сохраняется исходный JSON экспорта и его SHA-256. Проверяется целостность, принадлежность ресурсу и точный путь поля.
2. Код повторно рассчитывает фильтры, количества, порядок и строки по этому снимку. Для страницы дерева повторно вычисляются дети и пагинация.
3. Отдельно отображается покрытие распознанных частей вопроса. Сверка чисел не доказывает, что выбран правильный смысл вопроса.
4. Кнопка проверки утверждений запускает отдельную модель: она выбирает готовые фрагменты/факты, код проверяет ссылки и цитаты. Это дополнительная оценка смысла, не гарантия истины.

Снимок может быть старым, а сама база содержать ошибку. Для свежести есть сверка изменений/перезагрузка индекса и отметка резервного снимка. Ни один зелёный индикатор не означает 100% правильности естественно-языкового понимания.

## Дерево и depth

Раньше Web запрашивал фиксированную глубину, а слишком широкий подграф превышал ограничение 100 вершин и превращался в непонятный 502. Теперь раздел «Ресурсы» получает только непосредственных детей по 20: раскрытие узла загружает его следующую ветку, кнопка продолжения — следующую страницу. Потомки не добавляются в DOM заранее. Первый запрос всё ещё может загружать полный экспорт с платформы; далее используется индекс/кеш.

Новый MCP `get_children(path, root, offset, limit, expected_snapshot)` возвращает `total`, `has_more`, `next_offset`, точные пути и источник. Страницы привязаны к SHA-256, при смене снимка возвращается 409: сверните ресурс, при необходимости обновите индекс, откройте заново. Старый `get_subgraph` сохраняет честную семантику depth (число уровней). Если результат больше 100 вершин, код `subgraph_too_large`, Web 413 и подсказка перейти на страницы; глубина не уменьшается скрыто.

В предметном запросе структуры можно передать `subject="Справочник по материалам", structure_root="Сплавы на основе железа"`. Вариант с полным путём в subject также распознаётся. Несуществующая ветка не заменяется корнем справочника. Список детей поддерживает offset/limit и продолжение.

## Циклы агента

Увеличение 12 до 30 шагов даёт больше попыток, но не устраняет повторение. Адаптивный runtime теперь:

- Не выполняет повторно успешный идентичный запрос; передаёт модели ID уже полученного источника.
- Считает новые данные, исключая изменившиеся подписи, время и служебные поля. После нескольких попыток без прогресса останавливается с проверенными частичными результатами и причиной.
- Сохраняет результаты при исчерпании шагов/вывода или ошибке локальной/облачной модели; не выдаёт их за полный ответ.
- Передаёт Ollama `think=false`. Если провайдер всё равно возвращает только thinking без JSON-решения, показывает диагностику совместимости модели/JSON Schema. По скриншоту нельзя установить, что причиной конкретного удалённого цикла был именно thinking: нужна трасса решения и инструментов.

Настройки `.env`: `AGENT_MAX_STEPS=12` (1–60), `AGENT_MAX_STAGNANT=3` (1–5), `AGENT_MODEL_TIMEOUT=180` (1–600 секунд на локальный запрос модели). Последняя не ограничивает всю длительность диалога. Для облачных провайдеров действуют таймауты их клиента. `OLLAMA_NUM_PREDICT` — лимит генерации решения, а не число шагов. CLI `--max-steps` переопределяет общий бюджет. После изменения окружения пересоздайте контейнер: `docker compose up -d --build`. Ollama работает отдельно и не выгружается после каждого вопроса.

## Прочность и применение

«Больше углерода» и «самый прочный» — разные вопросы. Текущий предметный рейтинг вычисляет границы элементного состава; он не располагает измерениями прочности всех сплавов в одинаковых условиях. Для «лучшего сплава для ракетостроения» также нужны заданные показатели и условия. Поэтому такие запросы требуют критериев до длительного обхода графа. Если пользователь явно просит рейтинг по составу как приближение, результат сопровождается ограничением: прочность/применимость не подтверждены. Выбор ВТ20Л на скриншоте сам по себе не доказывает обоснованную рекомендацию.

## Проверка изменений

Добавлены автоматические сценарии большого дерева, страниц/изменившегося снимка, повторного расчёта и подмены поля, структуры конкретной ветки, отсутствующей ветки, повторов при бюджете 30, ответа только thinking, исчерпания вывода и недопустимого рейтинга. Проверки используют MockBackend и HTTP-заглушки, не вызывают платные модели и не изменяют выданные ИР. Реальная скорость модели одногруппника и её конкретная трасса этими тестами не воспроизводятся.
