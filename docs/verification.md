## Реальная платформа и модель

Подключён настоящий аккаунт IACPaaS, чтение исходных восьми ИР проверено. Экспорт, поиск, подсчёт и подграфы работают через HttpBackend. Сохранённые реквизиты защищены Windows DPAPI и исключены из Git. Истёкший сохранённый JWT обновляется для того же аккаунта; автоматически повторяются только GET-запросы.

Модель `qwen-agent` работает через Ollama на 127.0.0.1:11435, окно Python-приложения 32768, бюджет входа около 24000, выход до 2048 на решение. Qwen остаётся в памяти между вопросами и выгружается при штатной остановке приложения.

## Протокол, ошибки и запись

Оба транспорта проверены: настоящий stdio-подпроцесс и локальный Streamable HTTP с Bearer. Без токена и с неверным токеном HTTP отклоняет доступ. У обоих транспортов общий build_server и доменная логика.

Типы выходов всех десяти MCP-инструментов проверяются до выдачи. Ошибки имеют JSON code/message/retryable/tool/suggestion. Проверены неизвестный ИР, недопустимая глубина, ограничения размера, запрещённая запись, предпросмотр, отказ, подтверждение, истечение/одноразовость токена и повторное чтение результата. Адаптивный цикл возвращает ошибку модели для исправления плана и сохраняет собственные решения и аргументы вызовов в контексте.

Штатный сайт оставлен в режиме чтения. Для показа записи есть отдельный `python -m iacpaas_mcp.demo`: он создаёт синтетические собственные ресурсы в MockBackend и допускает изменение только точных данных манифеста. Исходный учебный граф и выданные ИР защищены проверками. `--live` отдельно запрашивает согласие человека на создание двух новых собственных ресурсов в платформе; `--accept-mock` для него запрещён. С согласия пользователя живой импорт двух новых собственных ИР прошёл: онтология 4 вершины/3 дуги, база 7 вершин/6 дуг. Update API вернул серверную ошибку updateVertice; статус не изменился, успех обновления не заявляется. Отдельная невозобновляемая диагностика и повторное чтение описаны в [live-write-demo.md](live-write-demo.md).

## Границы проверки

- Правильность понимания естественного языка не гарантируется на 100%. SHA-256 подтверждает целостность снимка, повторный расчёт — воспроизводимость по нему.
- Поиск охватывает подключённые пути, а не автоматически весь фонд аккаунта. Бинарные вложения не индексируются.
- Предметный API ограничен поддерживаемыми операциями. Произвольные соединения и несколько независимых числовых условий могут потребовать уточнения.
- Основной Python runtime адаптивный; LangChain не используется. ТЗ допускает сопоставимый runtime. Прежний knowledge и экспериментальный raw сохранены отдельно.
- Реальные облачные генерации не выполнялись без ключей; контрактные проверки пяти провайдеров используют HTTP-заглушки.
- Финальный текст IDE формирует VS Code, а не Python-верификатор; сверяйте раскрытые результаты MCP.
- Локальные трассы, снимки, история и аккаунты не публикуются. Новые собственные данные демонстрации синтетические и не подменяют исходные базы материалов.
