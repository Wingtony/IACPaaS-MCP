# Доработка предметных запросов и собственных ресурсов

## Условия и страницы

`query_knowledge` принимает `conditions` (до 16) и `condition_mode: all | any`. Операторы: `lt`, `le`, `gt`, `ge`, `present`, `absent`. Числовой порог — конечное число от 0 до 100. Сервер проверяет весь граф, применяет условия и только затем ограничивает вывод. Старый одиночный фильтр совместим с новым API.

```json
{"operation":"filter","conditions":[{"element":"Cr","op":"le","value":19},{"element":"Ni","op":"ge","value":9}],"condition_mode":"all","offset":0,"limit":10}
```

Для ≤ проверяется верхняя допустимая граница, для ≥ — нижняя: условие должно выполняться на всём записанном диапазоне. Формулы и неизвестные границы не превращаются в числа. `present` включает запись `0%`; `absent` означает, что компонент не указан, и не доказывает химическое отсутствие вещества. `include_unlisted` — только явное включение неуказанных элементов в lt/le; по умолчанию выключено.

Результат содержит `total`, `offset`, `limit`, `has_more`, `next_offset`, `dataset` и ссылки на исходные вершины. Для следующей страницы сохраняются фильтры, класс и порядок. Передайте `dataset` из предыдущей страницы: изменение графа заставит начать поиск заново. В Web добавлены кнопка следующей страницы и понимание «покажи следующие десять». Неизвестные классы/неполностью разобранные составные условия вызывают уточнение, а не молчаливую потерю фильтра. Условия плоские: все И либо все ИЛИ; вложенные логические группы отдельно не реализованы.

Банк примеров содержит 39 вопросов. Это вопросы и планы для регрессии, **не таблица заранее заготовленных ответов**: интерфейс отправляет текст вопроса, модель выбирает инструменты, числа/строки рассчитывает сервер по данным.

## Собственные ресурсы

Запись выключена по умолчанию. Для неё явно настройте:

```dotenv
IACPAAS_ALLOW_WRITE=true
IACPAAS_WRITE_ROOTS=["АТЛАС мои ресурсы"]
```

В Docker измените deployment `.env` и пересоздайте контейнер. Область записи — ваша папка вне «Загрузок». Сервер запрещает изменение «Загрузок», выданных подключённых ресурсов, их родителей и любых путей вне разрешённых корней. Нормализуются Unicode, разделители, регистр, префикс «Мой Фонд»; пути с `..` и процентным кодированием отклоняются. Корень области нельзя удалить/заменить.

Новые инструменты:

| Инструмент | Назначение |
|---|---|
| `create_folder` | Создать свою папку с подтверждением |
| `validate_tree` | Проверить дерево по подключённой онтологии без записи |
| `create_resource` | Собрать универсальный JSON на сервере, показать дерево, получить подтверждение, импортировать и перечитать |
| `delete_inforesource` | Перенести свой ИР в корзину; `deleteIR` только при явном выборе и подтверждении |
| `index_status` | Показать состояние локального индекса |
| `sync_resources` | Сверить даты или принудительно обновить выгрузки |

Пример дерева для собственной онтологии проектов:

```json
{"folder_path":"АТЛАС мои ресурсы","ontology_path":"Путь/Онтология проектов","title":"Мои проекты","items":[{"concept":"Проект","name":"Web","children":[{"concept":"Сценариев","value":3}]}]}
```

Имена понятий берутся из реальной онтологии через чтение MCP. Валидатор проверяет допустимых непосредственных потомков, обязательность «в точности один»/«непустое множество», типы STRING/INTEGER/REAL/BOOLEAN, уникальность имён соседей, ограничение глубины 8 и размера 250 вершин. Ссылки/клоны, альтернативы и неподдерживаемые типы **отклоняются**, а не угадываются. Это ограничение конструктора; не заявляется поддержка всех конструкций произвольной онтологии IACPaaS.

Создание требует подтверждённого отсутствия целевого ИР. Ошибка прав/сети не считается признаком отсутствия. Сервер никогда не включает очистку при `create_resource`. После импорта сверяются значения и структура дерева с повторным чтением без учёта ID/дат/порядка соседей. Если перечитать нельзя, результат честно сообщает о выполненном импорте и непроверенном чтении; автоматически повторять запись нельзя. Успешно созданные пути сохраняются в конфигурации; удалённые исключаются.

MCP elicitation показывает конкретные аргументы операции человеку. Клиент без поддержки подтверждения не может писать. Старый preview-token сам по себе больше не разрешает запись; действует одноразовое подтверждение, привязанное к аргументам и сроку. Web/CLI используют тот же механизм; модель не может подтвердить сама. Тесты проверяют принятие и отказ, повторное создание и попытку удаления выданной базы. Живых новых операций записи при этой доработке не выполнялось.

## Свежесть и проверка утверждений

TTL индекса остаётся 5 минут. После истечения сверяется дата корня: неизменённый граф не скачивается повторно, изменённый — переиндексируется. Без достоверной даты выполняется полная выгрузка. Кнопки во вкладке «Ресурсы» позволяют сверить изменения или загрузить всё заново. Резервный снимок допустим только при недоступности платформы и успешной проверке SHA; ошибки авторизации/прав не маскируются резервом. Ответ явно показывает резервный источник и дату. В метаданных есть происхождение, возраст и полнота покрытия; кэш не гарантирует мгновенную свежесть в пределах TTL.

Кнопка **Проверить утверждения** запускает отдельный LLM-запрос по завершённому ответу и успешным MCP-результатам. Можно задать `VERIFIER_MODEL` другого ID того же провайдера. Проверяющий возвращает точную цитату ответа, статус и JSON Pointer к источнику. Приложение сверяет цитату и значение поля; выдуманная опора снимает подтверждение. Если весь материал не помещается в контекст, проверка отказывается от вердикта. Облачная проверка — явный дополнительный оплачиваемый запрос с данными ответа/инструментов.

Смысл утверждения оценивает модель. Точное совпадение цитаты и поля проверяет код. Ни один этап не даёт 100% гарантии истинности базы или правильности понимания пользователя. Детерминированный пересчёт и сверка исходных снимков сохранены как отдельный уровень проверки.

## Проверка Unix-ветки

Проверена `origin/dev_unix_support`, commits `38ddc18` и `8b84406`. В ней полезны разделение Windows/Unix и стандартный Unix-порт Ollama. Shell-скрипты оказались незавершёнными: неверный путь к venv и зависимость от GUI. Вместо слепого слияния добавлены переносимые Python-команды, рабочие shell-обёртки, POSIX-хранилище секретов и Docker. Авторские коммиты не переписывались; ветка одногруппника не удалялась. Основной способ эксплуатации теперь [Docker + отдельная Ollama](docker.md), нативный запуск — дополнительный вариант.
