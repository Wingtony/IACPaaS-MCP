# Совместная работа

Репозиторий предназначен для приватной совместной разработки. Владелец приглашает участников через GitHub Settings → Collaborators. Для создания веток и отправки изменений нужен доступ на запись. Ссылка на приватный репозиторий работает только у приглашённых участников после принятия приглашения.

## Первое подключение

1. Примите приглашение GitHub и склонируйте репозиторий.
2. Создайте Python 3.11 окружение и установите зависимости по README.
3. Скопируйте `.env.example` в `.env`. Для обычных тестов оставьте `IACPAAS_BACKEND=mock`: аккаунт IACPaaS и Qwen не нужны.
4. Для настоящих запросов настройте собственную модель Ollama и доступ IACPaaS. Данные владельца проекта, выгрузки базы и веса модели в репозиторий не входят.

## Ветка и pull request

```sh
git switch main
git pull --ff-only
git switch -c feature/short-description
# внесите изменения
git add path/to/changed-file
git commit -m "Describe the change"
git push -u origin feature/short-description
```

После отправки ветки откройте pull request в `main`. В описании укажите, что изменилось и как проверено. Исправления удобно называть `fix/short-description`. Примеры имён — соглашение проекта; запрет прямых изменений main отдельно настраивается владельцем в правилах GitHub и здесь не считается уже включённым.

## Проверки

В Windows после установки зависимостей:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Эти тесты работают на учебных данных и заглушках; реальную модель не загружают. Реальные прогоны `scripts/benchmark_agent.py` запускаются отдельно, используют локальный аккаунт и могут занимать RAM/VRAM.

Не добавляйте `.env`, `.local`, журналы, историю диалогов, реальные экспорты, пароли и токены. Для новых тестов используйте искусственные fixtures. Локальная `.mcp.json` зависит от путей на компьютере и исключена из Git; переносимая конфигурация VS Code находится в `.vscode/mcp.json`.
